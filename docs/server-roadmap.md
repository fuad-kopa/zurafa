# Зурафа: сервер и дорожная карта

Дата: 2026-09-27. Текущее состояние: статический сайт (Vite) на GitHub Pages, онлайн по ссылке через
Trystero (P2P, публичные nostr-ретрансляторы), профиль и рейтинг только в localStorage браузера.

## 1. Чего не хватает по сравнению с лучшими шахматными приложениями

Сравнивались Chess.com, Lichess, Chessable, Play Magnus, ChessKid, Aimchess, Pychess (сервер вариантов).

| Что есть у лидеров | У нас | Приоритет |
|---|---|---|
| Аккаунты, рейтинг на сервере, подбор соперника, переподключение, зрители | только ссылка P2P, рейтинг локальный | 1 |
| Партии по переписке (ход раз в день), уведомления «ваш ход» | нет | 2 |
| Экспорт/импорт партий (PGN), ссылка на партию, картинка позиции для соцсетей, редактор позиции | нет | 2 |
| Турниры (арена), таблица лидеров, друзья, клубы | нет | 3 |
| Задачи по темам, режим «на время» (rush/storm), повторение с интервалами | 18 задач, задача дня | 2 |
| Уроки с ветвлением и видео, курсы | статичные страницы + задачи | 3 |
| Дебютная база из сыгранных партий, серверный анализ глубже | движок в браузере | 3 |
| Боты с характером (агрессивный, позиционный), «играй как X» | 6 уровней силы | 3 |
| PWA офлайн (service worker), нативные обёртки для магазинов | только manifest | 2 |
| Достижения, серии, еженедельные события | серия задачи дня | 3 |
| Античит, жалобы, модерация | нет (нет смысла без сервера) | после п.1 |
| Режим «вслепую», премувы, подтверждение хода, зен-режим | клавиатура, подсказки | 3 |
| Аналитика и отчёты об ошибках | нет | 2 |

Наше преимущество, которого нет ни у кого: единственное живое приложение именно по шахматам Тамерлана:
битвы на картах, история, резной комплект, шесть языков. Сервер превращает это из «демо» в сообщество.

## 2. Архитектура на своём сервере

```
zurafa.app            → Caddy (HTTPS автоматически) → статика из /srv/zurafa/www
zurafa.app/ws         → Node 22 игровой сервер (WebSocket)   :8787
zurafa.app/api        → тот же Node (REST: аккаунты, профиль, партии, рейтинг)
PostgreSQL 16         → пользователи, партии, рейтинги, задачи, турниры
```

Одна машина на 2 ГБ памяти тянет тысячи одновременных партий: ходы легковесные, движок на сервере не нужен
(проверка легальности хода — наш же TypeScript-движок, он работает в Node без изменений).

## 3. Пошагово

### Шаг 0. Что нужно от вас
- ОС сервера (лучше Ubuntu 22.04/24.04) и доступ по SSH: `ssh user@IP`.
- Домен: `zurafa.app` (и `timurchess.ru` редиректом). В DNS: запись `A` на IP сервера для `zurafa.app` и `www`.
- Почтовый отправитель для входа по ссылке (любой SMTP: Resend, Postmark, Яндекс 360). Нужны хост, логин, пароль.

### Шаг 1. Базовая настройка (10 минут)
```bash
sudo apt update && sudo apt install -y caddy postgresql-16 ufw fail2ban rsync
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash - && sudo apt install -y nodejs
sudo ufw allow OpenSSH && sudo ufw allow 80 && sudo ufw allow 443 && sudo ufw enable
sudo mkdir -p /srv/zurafa/www /srv/zurafa/server && sudo chown -R $USER /srv/zurafa
```

`/etc/caddy/Caddyfile`:
```
zurafa.app, www.zurafa.app {
  root * /srv/zurafa/www
  encode zstd gzip
  handle /ws* { reverse_proxy 127.0.0.1:8787 }
  handle /api* { reverse_proxy 127.0.0.1:8787 }
  handle { try_files {path} /index.html; file_server }
  header /video/* Cache-Control "public, max-age=604800"
  header /music/* Cache-Control "public, max-age=604800"
}
timurchess.ru, www.timurchess.ru { redir https://zurafa.app{uri} permanent }
```
`sudo systemctl reload caddy` — сертификаты Caddy получит сам.

### Шаг 2. Выкладка статики со своего компьютера
В `deploy.sh` добавляется одна строка после сборки:
```bash
rsync -az --delete dist/ user@zurafa.app:/srv/zurafa/www/
```
GitHub Pages остаётся как зеркало, ничего ломать не нужно.

### Шаг 3. Игровой сервер (делаю я, 2–3 дня)
- `server/` в этом же репозитории: Node + `ws` + `pg`. Комнаты, seeks («ищу партию 10+5»), ходы с проверкой
  легальности нашим движком, часы на сервере, переподключение по токену, зрители, чат, реванш.
- Клиент: `src/net/online.ts` получает второй транспорт `server` вместо Trystero; ссылки `#/g/<room>` работают
  как раньше. P2P остаётся запасным режимом, если сервер недоступен.
- Запуск: systemd-юнит `zurafa.service`, перезапуск при падении, логи в journald.

### Шаг 4. Аккаунты и рейтинг (делаю я, 2–3 дня)
- Вход по ссылке на почту (без паролей) плюс гостевой аккаунт, который потом «повышается» до полного.
- Локальный профиль сливается с серверным при первом входе (история партий и рейтинг переносятся).
- Рейтинг Glicko-2 по контролю времени (блиц/рапид/переписка) и отдельно с компьютером.
- Таблица лидеров, страница игрока с партиями и разбором.

### Шаг 5. Партии по переписке и уведомления (1–2 дня)
- Ход раз в сутки, список «ваш ход» в профиле, web-push через service worker, письмо при бездействии.

### Шаг 6. Турниры, друзья, задачи из партий (по неделе на блок)
- Арена по выходным; друзья и приглашения; автогенерация задач: сервер прогоняет сыгранные партии движком
  и отбирает позиции с единственным выигрывающим ходом.

### Шаг 7. Эксплуатация
- Бэкап: `pg_dump` каждую ночь в отдельное хранилище (S3/Backblaze), проверка восстановления раз в месяц.
- Мониторинг: UptimeRobot на `/api/health`; лог ошибок клиента в `/api/log`.
- Обновления: `unattended-upgrades`; ключи SSH вместо паролей; fail2ban уже стоит.

## 4. Порядок работ и сроки
1. Шаги 0–2: вы даёте доступ и домен, я настраиваю за один вечер.
2. Шаги 3–4: неделя, после чего онлайн-партии и рейтинг работают по-настоящему.
3. Шаги 5–6: по мере желания, каждый блок отдельно тестируется на живых игроках.
